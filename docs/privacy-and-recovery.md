# Privacy and recovery

## Installed and embedded hosts

The following guarantees apply to the installed, service-backed Placekeeper hosts, not to the front-end-only web beta. Placekeeper binds its service to `127.0.0.1`, uses scoped launch capabilities, and keeps PDF bytes, drafts, exports, SyncTeX hints, and live Codex context on this Mac. No installed adapter uploads documents, forwards a port, or requests network access. Live context is available only to the Codex task whose successful launch was claimed by the packaged hook and activated by that launch's authenticated browser. It is never inferred from an active tab, recent file, URL, or another task. Ordinary Codex sandbox and permission controls remain authoritative for any source work.

Readable review URLs deliberately contain the PDF's absolute local path plus a page or saved-item fragment. Treat copied Placekeeper links like local filenames: they contain no capability, browser credential, session ID, task ID, or Codex binding, but the path itself may be sensitive. Live refresh authorization stays in an HttpOnly cookie and daemon memory. A replacement daemon can recover only the path and safe location from an old URL; reopening requires a click and the ordinary unfamiliar-path confirmation, creates a fresh browser-scoped view, and does not recover unsaved viewer state or old authority. That fresh view may regain the exact owning Codex task association only through a separate short-lived restart ticket whose private browser token and next owning-task prompt both match; the URL and Placekeeper Link remain non-authoritative.

Recoverable snapshots live under `~/Library/Application Support/Placekeeper`. Mutable data never belongs inside the signed app bundle. Closing a live session, ending the hosting task, changing document generation, or allowing its lease to expire revokes live context without deleting the saved PDF. Prompt context contains semantic state and an opaque, short-lived evidence handle; it does not contain browser capabilities, bind proofs, loopback URLs, absolute document paths, or PDF bytes. Evidence retrieval is read-only, bounded, and denied to another task or stale document generation. Recovery cleanup cannot erase copies already captured by APFS snapshots, Time Machine, cloud backup, or user-created exports. Removing Placekeeper does not remove recovery data; remove that directory separately only after confirming no draft is needed.

Default Save creates a collision-safe `*-reviewed.pdf` and leaves the source unchanged. A clean rebuild requested in the bound Codex task remains distinct from the annotation-bearing PDF. Failed persistence retains the acknowledged draft. Replace Original is a separate explicit action and fails closed on drift, signatures, encryption, permissions, or filesystem identity changes.

## Front-end-only web beta

The web beta is a different, export-only host. It has no backend, account, Placekeeper cookie, analytics, application telemetry, autosave, recovery store, service worker, or intentional use of durable browser storage. Review State and PDF bytes exist only in the active tab's memory. A browser back/forward cache suspension may preserve that live tab, but closing the tab or confirming a reload discards the review. Placekeeper cannot recover it. **Export is the only durability action.**

For a locally selected PDF, Placekeeper processes the bytes in the current tab and does not upload them. GitHub Pages still serves the application assets and may log ordinary site-request metadata under GitHub's policies, such as the request address, time, and network information. The browser, operating system, DNS resolver, enterprise network, extensions, security software, and their logs remain outside Placekeeper's control.

Opening a remote PDF is an explicit direct request from the browser to the URL's host. Placekeeper requests it with browser-managed credentials omitted and no referrer, but this does not make the request anonymous or secret. The host receives the complete URL, including query parameters or signed tokens, and normally receives the reader's IP address and a CORS `Origin` naming the Placekeeper site. DNS and intervening networks may also observe connection metadata. A CORS error occurs after the request may already have reached the host. Placekeeper cannot prove that a hostname resolves only to public addresses, so use remote URL opening only for non-sensitive public resources. If a URL fails, download the PDF through the browser or another trusted route and then choose the local file.

The launcher rejects files larger than 64 MiB (67,108,864 bytes), obvious non-PDF input, credential-bearing or non-HTTPS remote URLs, redirects, and obvious local or private destinations. These controls bound common risks; they do not make an untrusted PDF safe. The project site uses a GitHub Pages origin shared with other pages and detects some framed, retained-opener, and service-worker states, but those are partial mitigations rather than origin isolation. Do not use this beta for confidential PDFs.

Export rewrites a snapshot into a new reviewed-copy download. Before asking the browser to download, Placekeeper reopens the generated bytes and checks the page count and expected Placekeeper-owned annotations, portable identities, and normal appearances. That is a narrow structural check, not comprehensive content verification or sanitization. Other source PDF content is preserved; active, linked, or embedded content is not promised to be detected or removed. The browser may block a download, rename it, or place it somewhere unexpected, and Placekeeper can confirm only that download initiation was requested—not that the file was retained. Keep the downloaded copy and reopen it independently before relying on it.

The five supported Review Item kinds are Replace, Delete, Insert, Highlight, and Page Note. Uploading a reviewed copy can restore valid Placekeeper-owned annotations as editable Review Items without duplicating their PDF projections. Preservation of foreign annotations and links is best effort and available only when the PDF passes rewrite-eligibility checks. Signed, encrypted, permission-restricted, malformed, stalled, or otherwise unexportable PDFs are rejected before authoring rather than opened with a false promise of durability.
