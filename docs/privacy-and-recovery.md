# Privacy and recovery

Placekeeper binds its service to `127.0.0.1`, uses scoped launch capabilities, and keeps PDF bytes, drafts, exports, SyncTeX hints, and live Codex context on this Mac. No adapter uploads documents, forwards a port, or requests network access. Live context is available only to the Codex task whose successful launch was claimed by the packaged hook and activated by that launch's authenticated browser. It is never inferred from an active tab, recent file, URL, or another task. Ordinary Codex sandbox and permission controls remain authoritative for any source work.

Recoverable snapshots live under the stable compatibility state path `~/Library/Application Support/PDF Proofreader`. That legacy technical name is retained so existing Placekeeper drafts survive in-place upgrades without a state copy or migration. Mutable data never belongs inside the signed app bundle. Closing a live session, ending the hosting task, changing document generation, or allowing its lease to expire revokes live context without deleting the saved PDF. Prompt context contains semantic state and an opaque, short-lived evidence handle; it does not contain browser capabilities, bind proofs, loopback URLs, absolute document paths, or PDF bytes. Evidence retrieval is read-only, bounded, and denied to another task or stale document generation. Recovery cleanup cannot erase copies already captured by APFS snapshots, Time Machine, cloud backup, or user-created exports. Removing Placekeeper does not remove recovery data; remove that directory separately only after confirming no draft is needed.

Default Save creates a collision-safe `*-reviewed.pdf` and leaves the source unchanged. A clean rebuild requested in the bound Codex task remains distinct from the annotation-bearing PDF. Failed persistence retains the acknowledged draft. Replace Original is a separate explicit action and fails closed on drift, signatures, encryption, permissions, or filesystem identity changes.
